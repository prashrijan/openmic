## 1. Overview

OpenMic v0.1 is a web application where a user picks a communication scenario, has a text conversation with an AI partner playing a defined role, and receives an actionable feedback report at the end. Guest users can complete a limited number of sessions before signing up. Signed-in users can review past sessions and their feedback.

## 2. Terminology

| Term | Definition |
|---|---|
| **Session** | One continuous conversation between a user and the AI, from start to end. |
| **Scenario** | A pre-authored practice setup (title, description, AI's role, suggested difficulty). |
| **Custom topic** | A user-authored free-text description of what they want to practice, instead of picking a scenario. |
| **Roleplay** | The AI adopts a specific character (interviewer, colleague, friend, etc.) for the duration of a session. |
| **Feedback mode** | The style of coaching: **natural-flow** (feedback only at end) or **coach** (inline nudges during the chat). |
| **Feedback report** | An end-of-session summary generated by the AI: strengths, growth areas, and 1–3 concrete suggestions. |
| **Guest** | A user who has not signed up. Identified by browser session; can complete up to 2 sessions before signup is required. |

## 3. User Stories

User stories are grouped by flow. Each story states *who*, *what*, and *why*, and links to the functional requirements that implement it.

### 3.1 First-time visitor

- **US-1.** As a first-time visitor, I want to understand what OpenMic does within 10 seconds of landing, so I can decide whether to try it. *(→ FR-0.1, FR-0.2)*
- **US-2.** As a first-time visitor, I want to try a real practice session without creating an account, so I can experience the value before committing. *(→ FR-1.1, FR-2.1)*
- **US-3.** As a first-time visitor, I want to pick what I want to practice (interviews, small talk, meetings, ESL fluency, general), so the experience is relevant to me. *(→ FR-1.2)*

### 3.2 Session start

- **US-4.** As a user, I want to browse curated practice scenarios grouped by category, so I don't have to think up my own. *(→ FR-2.2)*
- **US-5.** As a user, I want to type a custom topic, so I can practice something specific to my life. *(→ FR-2.3)*
- **US-6.** As a user, I want to choose the AI's roleplay character, so the conversation feels realistic to the situation I'm preparing for. *(→ FR-2.4)*
- **US-7.** As a user, I want to choose difficulty (easy/normal/challenging), so I can stretch myself without being overwhelmed. *(→ FR-2.5)*
- **US-8.** As a user, I want to choose whether the AI gives inline feedback during the chat or waits until the end, so I can control the interruption level. *(→ FR-2.6)*

### 3.3 Conversation

- **US-9.** As a user, I want to type messages and get natural AI responses that stay in character, so the practice feels real. *(→ FR-3.1, FR-3.2)*
- **US-10.** As a user in Coach mode, I want gentle, occasional inline suggestions from the AI, so I improve mid-conversation without breaking flow. *(→ FR-3.3)*
- **US-11.** As a user, I want to end the session anytime with a clear button, so I never feel trapped. *(→ FR-3.4)*
- **US-12.** As a user, I want the AI to gracefully wrap up if the session approaches its time limit, so it doesn't cut off mid-sentence. *(→ FR-3.5)*

### 3.4 Feedback

- **US-13.** As a user, I want a short feedback report after each session that highlights what I did well, what to improve, and 1–3 specific things to try next time. *(→ FR-4.1)*
- **US-14.** As a signed-in user, I want to revisit past feedback reports, so I can track my growth. *(→ FR-4.2, FR-5.2)*

### 3.5 Signup & account

- **US-15.** As a guest who has used my free sessions, I want a clear, non-shaming signup prompt with an obvious "why sign up" message. *(→ FR-1.3)*
- **US-16.** As a user, I want to sign up with email or Google (Supabase Auth), so I don't have to remember another password. *(→ FR-5.1)*
- **US-17.** As a signed-in user, I want to see my last 30 sessions with their reports, so I can review my practice history. *(→ FR-5.2)*
- **US-18.** As a signed-in user, I want to update my profile (name, practice goals), so onboarding stays relevant. *(→ FR-5.3)*
- **US-19.** As a signed-in user, I want to delete my account and all my data with one action, so I'm in control of my privacy. *(→ FR-5.4, NFR-4.3)*

### 3.6 Trust & safety (baseline)

- **US-20.** As a user, I want to flag inappropriate AI behavior, so problems get caught without shutting the product down. *(→ FR-6.1)*

## 4. Functional Requirements

Each requirement has: **ID**, **description**, **acceptance criteria** (testable), and a **priority** (P0 = must ship, P1 = should ship, P2 = nice to have).

### 4.0 Landing & onboarding

**FR-0.1** *(P0)* — Landing page communicates value in ≤10 seconds
- Hero explains what OpenMic is and who it's for
- Primary CTA: "Try a session — no signup"
- Below the fold: 3 example scenarios, how it works in 3 steps, feedback report preview

**FR-0.2** *(P0)* — Practice-area picker
- On first visit, prompt user to pick from: Interviews / Meetings / Small talk / ESL fluency / General
- Selection persists in local storage for guests, in profile for signed-in users
- User can change it anytime from the header

### 4.1 Guest mode

**FR-1.1** *(P0)* — Guests can complete up to 2 full sessions without signup
- Guest identity tracked via signed browser cookie + IP-based rate limit
- Counter is visible ("1 of 2 free sessions used")
- After 2 sessions, signup wall replaces the "start session" button

**FR-1.2** *(P0)* — Practice-area selection is available in guest mode
- Same picker as FR-0.2

**FR-1.3** *(P0)* — Post-quota signup prompt is non-shaming and value-forward
- Explains 3 benefits: save history, revisit feedback, unlimited sessions
- Includes "sign up in 10 seconds with Google" as primary CTA

### 4.2 Session start

**FR-2.1** *(P0)* — Session can be started in ≤2 clicks from landing (guest happy path)

**FR-2.2** *(P0)* — Scenario catalog with 10–15 starter scenarios
- Grouped by category: Interviews / Meetings & Work / Small talk & Networking / ESL Fluency / Difficult Conversations
- Each scenario shows: title, one-line description, suggested AI role, suggested difficulty
- Scenarios are seeded in the database, not hardcoded in the app

**FR-2.3** *(P0)* — Custom topic input
- Free-text field, 20–500 characters
- On submit, prefill scenario config with reasonable defaults and let user tweak

**FR-2.4** *(P0)* — AI roleplay picker
- Default: role suggested by scenario
- User can override: pick from ~8 preset roles or "custom" (free text, ≤100 chars)

**FR-2.5** *(P0)* — Difficulty selector (Easy / Normal / Challenging)
- Difficulty affects the system prompt only (e.g., "Challenging: push back, disagree, interrupt occasionally"). No separate UI.

**FR-2.6** *(P0)* — Feedback mode toggle (Natural-flow / Coach)
- Default: Natural-flow
- Persists per-user (profile) for signed-in users; per-session for guests

### 4.3 Conversation

**FR-3.1** *(P0)* — Text chat interface
- User types in an input; messages send on Enter (Shift+Enter = newline)
- AI response streams token-by-token
- Typing indicator visible while AI is composing

**FR-3.2** *(P0)* — AI stays in character
- System prompt enforces role, scenario, difficulty, feedback mode
- AI never breaks character to say "As an AI…" unless user asks
- Session context (last N messages) is passed on every turn

**FR-3.3** *(P1)* — Coach mode inline nudges
- In Coach mode only, AI may append a brief `[coach: ...]` note *at most once every 3 turns*
- Nudges are visually distinct from the roleplay message
- User can toggle off nudges mid-session

**FR-3.4** *(P0)* — End session button
- Always visible in the chat header
- Confirms: "End session and see feedback?"
- On confirm: freeze input, generate feedback report

**FR-3.5** *(P0)* — Time limit (15 minutes) with graceful wrap-up
- At 13 minutes: AI receives a system nudge to naturally wind down the conversation
- At 15 minutes: user input is frozen; feedback report is generated
- Timer is visible to the user

### 4.4 Feedback

**FR-4.1** *(P0)* — End-of-session feedback report
- Generated by a separate LLM call using the full session transcript
- Structure: 2–3 strengths / 2–3 growth areas / 1–3 concrete suggestions for next time
- Total length ≤300 words
- User can rate the report (👍/👎) — signal for feedback quality tuning

**FR-4.2** *(P1)* — Feedback report is persisted and viewable later (signed-in users)
- Guests see the report once but it isn't saved

### 4.5 Account

**FR-5.1** *(P0)* — Signup / signin
- Email (magic link) + Google OAuth via Supabase Auth
- After signup, user is offered to import their guest-mode session (if any)

**FR-5.2** *(P0)* — Session history
- Signed-in users see their last 30 sessions with: date, scenario/topic, session length, quick preview of feedback

**FR-5.3** *(P1)* — Editable profile
- Fields: display name, practice goals (multi-select from same categories as FR-0.2)

**FR-5.4** *(P0)* — Account & data deletion
- One-click "Delete my account" in settings
- Deletes user record, all sessions, all messages, all feedback reports
- Confirmation modal with "type DELETE to confirm"

### 4.6 Trust & safety

**FR-6.1** *(P1)* — In-session flag button
- User can flag the current AI message as inappropriate
- Flag is logged with session ID and message ID for review
- User is thanked; no moderation queue UI in v0.1

**FR-6.2** *(P0)* — Content policy
- System prompt instructs AI to refuse: sexual roleplay with minors, illegal advice, self-harm encouragement
- If Claude's own safety filter refuses, we surface a graceful message rather than an error

## 5. Non-Functional Requirements

### 5.1 Performance

**NFR-1.1** *(P0)* — Time to first AI token ≤2 seconds (p50) after user sends a message
**NFR-1.2** *(P0)* — Landing page LCP ≤2 seconds on cable connection
**NFR-1.3** *(P1)* — Feedback report generated ≤10 seconds after session ends
**NFR-1.4** *(P1)* — Session history list loads ≤1 second for 30 sessions

### 5.2 Availability & reliability

**NFR-2.1** *(P0)* — Target 99% uptime for v0.1 (allows ~7 hours downtime/month — realistic solo)
**NFR-2.2** *(P0)* — Session state is durable: if the user's tab crashes mid-session, they can resume from the last user message on refresh
**NFR-2.3** *(P0)* — All LLM calls are retried once on transient errors (5xx, timeouts) before surfacing to the user

### 5.3 Security

**NFR-3.1** *(P0)* — No API keys or secrets in client code. LLM calls proxy through Next.js server-side routes.
**NFR-3.2** *(P0)* — Supabase Row-Level Security (RLS) enabled on all user tables. A user cannot read or write another user's data.
**NFR-3.3** *(P0)* — Rate limit LLM endpoints per user (signed in) and per IP (guest): 20 messages/minute, 60 messages/hour.
**NFR-3.4** *(P1)* — CSRF protection on all state-changing routes (Supabase handles for auth; verify for custom endpoints).
**NFR-3.5** *(P1)* — Dependency scanning enabled (GitHub Dependabot on the repo).

### 5.4 Privacy

**NFR-4.1** *(P0)* — Privacy policy published before launch. Covers what we store, how long, and third parties (Anthropic, Supabase, Vercel, PostHog).
**NFR-4.2** *(P0)* — Session transcripts stored only for signed-in users. Guest transcripts kept only in memory during the session; discarded after feedback.
**NFR-4.3** *(P0)* — Data deletion (FR-5.4) is complete within 24 hours of request, including any backups.
**NFR-4.4** *(P1)* — Analytics events contain no PII (no message content, no email addresses).
**NFR-4.5** *(P1)* — Anthropic's zero-data-retention setting is enabled on the API account if available.

### 5.5 Accessibility

**NFR-5.1** *(P0)* — WCAG 2.1 AA baseline: color contrast ≥4.5:1, keyboard navigation, focus indicators, semantic HTML.
**NFR-5.2** *(P0)* — Chat is fully keyboard-operable (Tab/Shift+Tab, Enter to send).
**NFR-5.3** *(P1)* — Screen-reader-friendly: aria-live region announces new AI messages.
**NFR-5.4** *(P1)* — Respect `prefers-reduced-motion` for any animations.

### 5.6 Responsiveness

**NFR-6.1** *(P0)* — Fully usable at 375px width (mobile Safari baseline)
**NFR-6.2** *(P0)* — No horizontal scrolling on any viewport ≥360px

### 5.7 Observability

**NFR-7.1** *(P0)* — Error tracking via Sentry, capturing frontend and server errors with session-safe context
**NFR-7.2** *(P0)* — Structured logs for every LLM call: model, prompt tokens, completion tokens, latency, session ID (no message content in logs)
**NFR-7.3** *(P1)* — Product analytics via PostHog: session_started, message_sent, session_ended, feedback_report_generated, guest_signup_completed, feedback_rated. No PII.

### 5.8 Cost

**NFR-8.1** *(P1)* — Average LLM cost per completed session ≤$0.05 (Claude Haiku for turns, Sonnet for feedback report)
**NFR-8.2** *(P1)* — Total monthly infra cost for v0.1 (up to 100 active users) ≤$50

### 5.9 Legal & compliance

**NFR-9.1** *(P0)* — Terms of Service and Privacy Policy live before launch
**NFR-9.2** *(P0)* — Cookie consent banner if analytics cookies are used (PostHog can be configured to work without cookies for v0.1)
**NFR-9.3** *(P1)* — Age gate: signup requires user to confirm they are 13+ (COPPA baseline)

## 6. Data Requirements

Full schema is defined in [`03-architecture.md`](03-architecture.md). Below is the high-level entity list.

| Entity | Purpose | Key fields | Notes |
|---|---|---|---|
| `users` | Auth + profile | id, email, display_name, practice_goals[], created_at | Managed by Supabase Auth + profile table |
| `scenarios` | Seeded catalog | id, category, title, description, ai_role, difficulty | Read-only for users; edited by admin (Prashrijan) |
| `sessions` | One conversation | id, user_id?, guest_cookie?, scenario_id?, custom_topic?, ai_role, difficulty, feedback_mode, started_at, ended_at | Either user_id OR guest_cookie is set |
| `messages` | Individual turns | id, session_id, sender ('user'\|'ai'\|'coach'), content, created_at | Not stored for guest sessions |
| `feedback_reports` | End-of-session report | id, session_id, strengths, growth_areas, suggestions, rating | Not stored for guest sessions |
| `flags` | User-reported issues | id, session_id, message_id?, reason, created_at | Reviewed manually in v0.1 |
| `rate_limits` | Enforcement | key (user_id or ip), window, count | Or handled by Supabase Edge / middleware |

## 7. Integration Requirements

**INT-1** *(P0)* — Anthropic Claude API
- SDK: `@anthropic-ai/sdk` (Node)
- Models: `claude-haiku-4-5-20251001` for conversation turns, `claude-sonnet-4-6` for feedback report generation
- Streaming responses for turns; non-streaming for feedback report
- Prompt caching enabled on the system prompt

**INT-2** *(P0)* — Supabase
- Auth: email magic link + Google OAuth
- DB: Postgres with RLS
- Client: `@supabase/supabase-js` (browser) + `@supabase/ssr` (Next.js server helpers)

**INT-3** *(P0)* — Vercel hosting
- Preview deploys on every PR
- Production deploys from `main`
- Environment variables managed in Vercel dashboard

**INT-4** *(P1)* — Sentry error tracking

**INT-5** *(P1)* — PostHog product analytics (self-serve, free tier)

**INT-6** *(P2)* — Domain purchase (`getopenmic.com` or alternative)

## 8. Constraints

**C-1** — Solo developer, 5–10 hours/week
**C-2** — Free-tier infra where possible (Supabase, Vercel, PostHog free tiers)
**C-3** — Text-only in v0.1 (voice is v0.2)
**C-4** — English-only (localization is not in scope)
**C-5** — Web only (mobile app is v0.3+)
**C-6** — Anthropic Claude API is the required LLM provider for text (per [ADR-0001, forthcoming])

## 9. Out of Scope for v0.1

Explicitly deferred to later versions or never — do not accept feature requests in these areas during v0.1:

- Voice input / voice output (v0.2)
- Peer-to-peer practice matching (v0.3+)
- Games and structured drills (v0.3+)
- Progress tracking, streaks, gamification (v0.3+)
- Payments and subscription tiers (v0.4+)
- Mobile native apps (v0.4+)
- Non-English languages (indefinite)
- Video calls or avatars (indefinite)
- Admin dashboard / moderation queue UI (v0.3+; v0.1 uses direct DB access)
- Team / organization features (indefinite)
